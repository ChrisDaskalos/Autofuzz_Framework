# Hand-written libFuzzer harnesses

These fuzzers were written by hand (they are **not** generated by AutoFuzz).
The big difference from `Tests/legacy_thesis`: they link the **real firmware**
code, `Core/Src/protocol.c` and `Core/Src/servo.c`, compiled for the PC with
`-DUNIT_TEST`. The hardware (UART, timer, delay) is replaced by the stubs in
`test_common.h`.

```bash
make build                    # compile the 3 fuzzers into bin/
make fuzz                     # run each one for 60 s
make fuzz FUZZ_MAX_SECS=600   # run each one for 10 min
make clean
```

## Files

| File | What it does |
|---|---|
| `fuzz_protocol_session.c` | Sends a whole session (password, menu choice, many commands) line by line. |
| `fuzz_protocol_cmd.c` | One command per input; 1 byte = menu choice, longer = servo command. Stops a runaway `Servo_Ramp` after 1 s. |
| `fuzz_uart_dma.c` | Copy of the firmware's UART DMA idle-callback code from `main.c`. The first 4 input bytes are a fake "DMA bytes remaining" counter. |
| `fuzz_custom_mutator.c` | Custom libFuzzer mutator that builds valid and invalid protocol sessions. Linked into all three fuzzers. |
| `test_common.c/.h` | HAL stubs for the PC. Different from `Tests/legacy_thesis/test_common.*`. |
| `mock_protocol_multi.c` | An older mock version of the protocol. Not built; kept for reference. |
| `*.dict` | libFuzzer dictionaries (protocol keywords and numbers). |
| `corpus/` | Seed inputs (38 hand-written `seed_*`, 150 `autogen_*`, 168 `edge_*`). Read only. |
| `make_seeds_edge.py` | Script that wrote the `autogen_*` seeds (uses random, so output differs per run). |

Output (all ignored by git): `bin/` (binaries), `out/<name>.log`
(fuzzer log), `out/<name>/` (crash inputs), `work_corpus/` (new inputs
libFuzzer finds).

## Expected findings

A 10-second run already reports this, so `make fuzz` exits with an error:

| Finding | Where | Fuzzer |
|---|---|---|
| Signed integer overflow in `ComputeChecksumFromNumbers` (`angle + step` with large numbers, e.g. `2147483647,1,0`) | `Core/Src/protocol.c:159` | session, cmd |

`fuzz_uart_dma` finds nothing today (also not in 60 s). Older versions
reported a `memcpy` overflow, but only because the harness gave the DMA
counter values above 1024, which the real DMA hardware never gives.

## Known limitations

- `fuzz_uart_dma.c` uses the firmware's `DMA_BUFFER_SIZE` (1024). With
  `-max_len=128` the payload is at most 124 bytes; the rest of the buffer
  stays zero. The fake "bytes remaining" counter (first 4 input bytes) is
  limited to 0..1024, like the real DMA counter.
- The two `crash-*` files that were on the Desktop were not added. They are
  1-byte inputs, and they were most likely caused by a deliberate
  `memcpy(bad, "X", 2)` in `fuzz_protocol_cmd.c` (a bug in the harness, not
  the firmware). That line is removed; see the git log.
